# Continuous Assurance Model

XPeX uses a closed-loop assurance model:

```text
BUILD → CONNECT → OPERATE → PROVE → IMPROVE
```

## Build
Define source, ownership, policy, identity and expected controls.

## Connect
Attach approved providers, tools, data and runtimes through least-privilege interfaces.

## Operate
Execute within explicit permissions, budgets, environments and approval boundaries.

## Prove
Capture source, deployment, runtime, policy, tool, action, result and independent verification evidence.

## Improve
Feed findings, incidents, evaluation results, cost/performance data and assurance gaps back into architecture and policy.

## Continuous-assurance triggers

Re-evaluate when:
- code changes materially;
- model/provider changes;
- tool permissions change;
- sensitive data scope changes;
- an incident occurs;
- a new production environment is added;
- autonomy increases;
- financial/destructive authority expands;
- external standards materially change.

## Target state

At `TP4_CONTINUOUSLY_ASSURED`, evidence freshness and control effectiveness are continuously monitored.

No XPeX subject currently self-declares TP4.
