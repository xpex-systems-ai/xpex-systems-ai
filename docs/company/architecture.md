# XPeX Systems AI — Target Architecture V1

## Corporate layer

### XPeX Systems AI
Company, brand, governance and commercial umbrella.

## Control plane

### XPeX Systems Command
**Status: existing system / active foundation**

Responsibilities:
- System registry
- Asset registry
- Evidence registry
- Accounts and sources
- Cross-platform correlations
- Audit runs
- Deployment evidence
- Ownership and lineage
- Portfolio truth
- Company graph

The Command must not become a copy of every provider. It indexes, relates and proves.

## Execution layer

### GXEON
**Status: existing family / consolidation required**

Responsibilities:
- Agent orchestration
- Tool execution
- Task routing
- Workflow automation
- Human approval gates
- Execution logs
- Cost and result telemetry

## Intelligence layer

### NEXARA Intelligence Fabric
**Status: DESIGN TARGET**

NEXARA is not the company brand. It is the proposed intelligence-routing layer inside XPeX.

Target responsibilities:
- Model routing
- Provider routing
- Cost-aware model selection
- Capability-aware model selection
- Fallback
- Latency-aware routing
- Policy enforcement
- Prompt/runtime configuration
- Evaluation
- Usage telemetry

Potential providers include OpenAI, Hugging Face, OpenRouter and other approved model providers.

A provider connection does not equal endorsement, partnership or guaranteed availability.

## Evidence layer

Every important object should be able to link to:
- source
- source account
- code
- deployment
- runtime
- database/infrastructure
- agent execution
- approval
- result
- audit trail

## Public boundary

Private Company Command:
- credentials metadata
- internal evidence
- ownership
- audit findings
- repository details
- system relationships
- security findings

Public Company Platform:
- approved products
- approved metrics
- verified live status
- public case studies
- sanitized architecture
- partner/provider references
- public evidence summaries

Private evidence must never be exposed automatically.
