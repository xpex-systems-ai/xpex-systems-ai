# Governance & Evidence Standard

## Prime rule

**THE EXECUTOR DOES NOT APPROVE ITS OWN DELIVERY.**

## Public-claim policy

Public pages, investor materials and sales collateral may use only metrics that have an evidence source.

Examples:

Allowed:
- verified project count from registry;
- verified repository count;
- verified live deployments;
- audited source accounts;
- paid revenue backed by transaction evidence.

Not allowed without proof:
- invented users;
- estimated revenue presented as actual revenue;
- unverified partnerships;
- fabricated uptime;
- fictitious agent counts;
- valuation claims.

## Ownership classes

- PROPRIETARY — direct ownership evidence
- LICENSED — permitted third-party code/asset
- FORK — derived from upstream
- SHARED — access without ownership proof
- UNKNOWN — insufficient evidence

## System states

- DISCOVERED
- CLASSIFIED
- CORROBORATED
- CANONICAL_CANDIDATE
- CANONICAL
- DEPLOYED
- VERIFIED_LIVE
- COMMERCIAL
- LEGACY
- ARCHIVED

## Security gates

A system cannot be promoted to VERIFIED_LIVE PUBLIC if:
- active secret-exposure findings exist;
- source ownership is materially unclear;
- runtime cannot be verified;
- production status conflicts across sources;
- public exposure would leak private evidence.

## Financial truth

Use separate states:
- LEAD
- PROPOSAL
- CONTRACTED
- INVOICED
- PAID
- REVENUE_CONFIRMED

Never collapse them into one metric.

## Partner truth

Use separate states:
- TECHNOLOGY_USED
- INTEGRATION_AVAILABLE
- MARKETPLACE_LISTED
- PROGRAM_MEMBER
- FORMAL_PARTNER
- COSELL_PARTNER

Using a provider does not mean a formal partnership.
