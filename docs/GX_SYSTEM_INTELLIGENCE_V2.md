# GX System Intelligence V2 — Neural Transfer Contract

GX is the canonical AI copilot identity for the XPeX ecosystem.

"Neural transfer" in this architecture means transferring **governed machine-readable company knowledge**, not copying private ChatGPT memory or credentials into a public model.

## Knowledge layers

1. **System Registry** — canonical identity, role, stage and provider.
2. **Runtime Evidence** — verified deployments and observed provider state.
3. **Source Evidence** — repositories, commits, manifests and AI-BOMs.
4. **Media Evidence** — screenshots/assets classified E1/E2/E3/D1/X.
5. **Trust Evidence** — controls, passports, assurance state and unresolved gates.
6. **GX Retrieval Layer** — the copilot receives only the evidence appropriate to its audience and permission scope.

## System dossier contract

Every canonical system page/dossier must be able to answer:

- What is it?
- What problem does it solve?
- Is it canonical?
- Where is the source?
- Where is it deployed?
- What provider/environment is verified?
- What evidence proves the current state?
- Which screenshots/assets are admissible?
- What is still unproven?
- What security/trust evidence exists?
- What should GX say about it?

## Public vs operator GX

**Public GX** remains evidence-only/read-only.

A future **Operator GX** may receive authenticated internal context and tool permissions, but those permissions must be explicit, least-privilege, auditable and separated from the public surface.

No neural-transfer layer may include raw secrets, private keys, unrestricted tokens or hidden personal memory.

## Promotion

A system dossier can be promoted only when its evidence state supports the claim. Runtime state, media class and trust state remain independent dimensions.
