# XPeX Flagship Cases — External Review Pack

This page is the shortest path for a recruiter, technical partner or investor to understand what XPeX has actually built.

## 1. XPeX Systems Command

**Problem:** an AI-native company can have code, deployments, databases, accounts and agents spread across many providers with no canonical operational map.

**What XPeX built:** a Company Intelligence & Evidence OS designed to inventory provider assets, preserve native IDs/provenance, correlate systems and attach evidence without silently modifying the source systems.

**Engineering signals:** Next.js, TypeScript, Prisma/PostgreSQL, provider-adapter contract, fail-closed internal API foundation, evidence-first lifecycle.

**Observed runtime:** Railway staging deployment SUCCESS with PostgreSQL service present.

**What is not claimed:** production readiness. The source itself blocks production promotion until stronger identity/RBAC/token-vault controls and independent approval exist.

## 2. GXEON Wallet Command Center

**Problem:** agent/Web3 operations become dangerous when dashboards blur watch-only balances, pending bounty work, internal credits and settled money.

**What XPeX built:** a command center with explicit Money Truth boundaries, read-only monitoring, agent-marketplace discovery, MCP/framework integration and human-controlled signing boundaries.

**Engineering signals:** React/Vite/TypeScript, Vercel functions, Firebase/Firestore integration paths, Stripe, viem, MCP discovery, framework examples.

**Observed runtime:** Vercel production READY.
