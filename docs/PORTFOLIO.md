## What an external reviewer should understand in two minutes

### Who we are
An AI systems engineering company focused on agentic systems, evidence, governance and product infrastructure.

### What we build
Control planes, agent marketplaces, MCP/plugin infrastructure, audit systems, learning platforms and AI product tooling.

### What is alive
Only systems with provider-backed runtime evidence are described as deployed. Error/canceled projects remain recovery candidates.

### Where the code is
Canonical GitHub sources are referenced where the connected GitHub installation can verify them. Source outside that scope is not silently treated as verified.

### Where the runtime is
Vercel and Railway provider IDs/states are captured in machine-readable evidence.

### What problem each system solves
Every flagship must have one concise user problem and one demo path.

### What security exists
Default-deny policies, secret hygiene, source analysis, supply-chain validation, Trust Passports, bounded agent permissions and evidence-first claims.

### What evidence exists
Source commits, provider IDs, workflow results, deployment states, runtime observations and machine-readable admission records.

### Who Junior Sena is inside this
The founder is presented as an **Applied AI / Agentic Systems Engineer** whose portfolio is the operating infrastructure itself, not only a résumé description.

A recruiter, customer or investor should not need to reverse-engineer 100 experiments.

```text

  → architecture
  → trust/security
  → demo
  → case study
```

## Truth boundary

XPeX does not claim government/defense equivalence, external certification, customers, revenue or production autonomy unless separately evidenced.

A green badge proves the corresponding automated check passed. It is not an external certification.
