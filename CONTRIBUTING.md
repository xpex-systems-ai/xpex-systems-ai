# Contributing to XPeX Systems AI

## Core rule

**The executor does not approve its own delivery.**

## Change flow

```text
Propose → Implement → Verify → Review → Promote
```

## Evidence requirements

Changes that affect public claims, system status, production state or ownership should include evidence.

## Branching

Use scoped branches such as:
- `feat/...`
- `fix/...`
- `audit/...`
- `docs/...`

Critical company, security, production and financial changes should be reviewed before merge.

## Style

Prefer clear architecture, reversible changes, explicit status, machine-readable metadata when useful, minimum necessary permissions, and no secrets in source control.
