Use this skill when someone wants to understand whether XPeX Systems AI can help with a concrete business, engineering, agent or integration need.

## Workflow

1. Start with `xpex_enterprise_match_need` when the visitor describes a problem or goal.
2. Use `xpex_enterprise_get_solution_pack` for the strongest matching offering.
3. Use `xpex_enterprise_get_demo_pack` when technical evaluation or proof is requested.
4. Use `xpex_enterprise_get_agent_assets` for agent-platform, MCP, plugin or developer-tool interest.
5. Use `xpex_enterprise_get_fit` when a buyer wants to know why a capability fits their organization.
6. Use `xpex_enterprise_prepare_pilot` to produce a bounded pilot path.
7. Use `xpex_enterprise_contact_handoff` when the evaluator is ready to discuss integration.
8. Use `xpex_enterprise_discover` when another agent or machine needs the full public discovery manifest.

## Distribution rules

- Prefer high-fit discovery over broad unsolicited outreach.
- Do not fabricate customer interest, partnerships, contracts, procurement decisions or revenue.
- A system match is not a sale.
- A pilot blueprint is not a signed pilot.
- Preserve maturity labels and open gates.
- Never guarantee ROI, revenue, cost reduction or deployment outcomes.
- Never request or expose secrets, credentials, private customer data or regulated data.
- The public API is read-only and stateless.
- If a visitor wants production execution, route to a human/operator handoff instead of claiming autonomous authority.

## Mission

Bring the right XPeX capability to the organization that actually needs it — with evidence.
